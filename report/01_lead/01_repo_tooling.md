## 1. What was planned

Set the repository up as a uv-managed Python 3.11 project:

1. `pyproject.toml`: setuptools build, package `donorbridge`, Python `>=3.11,<3.12`.
   - Runtime dependencies: numpy, pandas, matplotlib, networkx>=3.1, pulp==2.9.0, highspy.
   - Dev group: pytest, nbformat.
   - Optional `oracle` extra: kep_solver, installed into the same environment as pulp 2.9.0.
   - Pytest settings: `testpaths = ["tests"]`, plus the `slow` and `oracle` markers.
2. `.python-version` containing `3.11`.
3. `uv lock` then `uv sync`, with `uv.lock` committed. If kep_solver conflicted with pulp==2.9.0, stop.
4. `requirements.txt` exported from the lock as a fallback for anyone without uv.
5. `.gitignore` covering Python, `.venv*`, `.ipynb_checkpoints` and `data/raw/`.
6. A GitHub Actions CI workflow that:
   - runs `uv sync --locked`;
   - checks that `requirements.txt` is up to date;
   - runs the unit and integration tests;
   - reports the number of skipped tests.
7. Prove that the oracle extra installs alongside pulp 2.9.0.

## 3. Deviations from the plan

### 3.1 The CI freshness check for requirements.txt re-exports in place, not to a temp file

- **Plan:** export to a temp file in CI and `diff` it against `requirements.txt`.
- **Problem:** `uv export` writes the exact command, including the `-o <path>` argument, into the
  file's header comment:

  ```
  # This file was autogenerated by uv via the following command:
  #    uv export --format requirements-txt --no-hashes --no-emit-project -o requirements.txt
  ```

  An export to a temp file therefore always differs from the committed file on line 2, so CI would
  always fail.
- **Fix:** CI runs the identical command (`-o requirements.txt`) and then fails if
  `git diff --exit-code -- requirements.txt` finds a change. The check works as intended and the
  error message tells the developer which command to run.
- **Rule:** the export command must stay exactly as written. Adding a flag such as `--locked`
  changes the header, so the check would fail until `requirements.txt` is regenerated.

### 3.2 Additions not in the spec

These are small, but they are worth knowing about:

- **Project metadata:** `pyproject.toml` has `version = "0.1.0"`, a one-line `description` and
  `readme = "README.md"`.
- **Build backend:** setuptools is pinned to `>=68` for the build backend.
- **`.gitignore`:** also ignores build artefacts (`build/`, `dist/`, `*.egg-info/`), pytest and
  coverage caches, `.DS_Store`, `.vscode/` and `.idea/`.
- **CI actions:** CI uses `actions/checkout@v4` and `astral-sh/setup-uv@v6` with caching on.
- **CI skip count:** the step that writes the skip count to the job summary runs with
  `if: always()`, so the progress board appears even when tests fail. The integration step uses
  `set -o pipefail` so that piping its output through `tee` does not hide a failure.

## 4. Things to note

1. **CI will fail until test folders exist.** `tests/unit/` and `tests/integration/` do not exist
   yet. Pytest exits with an error when a path is missing, and with exit code 5 when it collects no
   tests. Before the first push, add the following:
   - `tests/conftest.py` (Lead);
   - `tests/unit/` with at least one test;
   - `tests/integration/` with at least one stub test (skipped is fine).
2. **A plain `uv sync` removes kep_solver.** `uv sync` makes the environment match the default set
   exactly. Anyone running oracle tests must use `uv sync --extra oracle` each time, or
   `uv run --extra oracle ...`.
3. **The allowed-dependency list needs updating.** The team rules allow only stdlib, numpy, pandas,
   matplotlib, networkx, pulp, highspy and pytest. This setup adds two more packages:
   - `nbformat`, in the dev group;
   - `kep_solver`, in the oracle extra.

   Both were deliberate Lead decisions, but the list in the project context should name them so
   that teammates do not flag them in review. Neither may be imported from the `donorbridge`
   package itself: kep_solver belongs only in `oracle/` and in tests marked `oracle`.
4. **`requirements.txt` is a fallback only.** It omits the oracle extra and the project itself
   (`--no-emit-project`). A pip user must also run `pip install -e .` to use the package. Its
   header says it was generated by uv, so nobody should edit it by hand.
5. **Updating dependencies:** whenever `pyproject.toml` changes, the Lead runs `uv lock`, then the
   export command, and commits `pyproject.toml`, `uv.lock` and `requirements.txt` together. CI
   catches a stale lock (`uv sync --locked`) or a stale export (`git diff`).
6. **Python patch version.** The lock downloaded a uv-managed CPython 3.11.16. Teammates do not
   need to install Python themselves; `uv sync` fetches it.
7. **CI does not run oracle or `slow` tests.** The integration step excludes `oracle`, and `slow`
   tests are opt-in. Cross-checks against kep_solver run locally only, for now.
